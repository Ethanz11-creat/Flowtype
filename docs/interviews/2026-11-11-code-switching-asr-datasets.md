调研日期：2026-11-11。需求依据：[科大讯飞岗位与面试准备需求](2026-11-11-iflytek-speech-llm-requirements.md)。

后续进展：已实际下载并完成 ASCEND validation 的音频完整性与词表覆盖检查，见[检查记录](../evidence/2026-11-11-ascend-validation-audit/README.md)。下文“未下载、未实验”描述的是最初资料调研阶段；后续记录也尚无 ASR 推理或主观试听结论。

补充调研：已找到 LibriSpeech contextual biasing、ContextASR-Bench、ConEC 等公开上下文评测资源，见[专项基准补充](2026-11-11-contextual-asr-benchmark-followup.md)。当前优先采用公开基准，自采作为仍有场景缺口时的补充，不作为开始评测的前置要求。

## 已确认目标与本轮边界

用户选择先讨论“上下文感知识别纠错”，场景为**中英混合技术口述**，希望先了解语音评测数据集。本轮核对公开论文、数据卡、元数据与许可，未下载音频、试听标注、运行模型或生成实验结果。本文是选型调研与实验建议，不是已经批准的开发设计。

建议将研究问题收敛为：在固定 ASR 输出的前提下，领域词表和历史上下文能否减少中英混合技术术语错误，同时控制无关上下文引起的误改？这是待验证的问题，不能预填提升幅度。

## 选型结论

推荐采用三层证据：**ASCEND 公共混说基线 → CS-Dialogue 历史上下文扩展（先核清使用条款）→ 自采真实技术口述专项集**。

| 数据集 | 已核实规模与内容 | 对本项目的用途 | 获取与许可边界 |
| --- | --- | --- | --- |
| [ASCEND](https://huggingface.co/datasets/CAiRE/ASCEND) | 10.62 小时、23 位说话人；香港自然中英对话；12,314 条，包含纯中、纯英及混说 | 优先建立可复现的公共混说基线 | 数据卡 CC-BY-SA-4.0；当前 API 标记非 gated；未验证音频下载 |
| [CS-Dialogue](https://huggingface.co/datasets/BAAI/CS-Dialogue) | 104.02 小时、200 人、100 场双人对话、38,917 条；包含长录音与短句索引 | 更适合检验历史上下文及错误传播 | CC-BY-NC-SA-4.0，另有明确非商用与分发限制；访问状态见下文 |
| [TALCS](https://arxiv.org/abs/2206.13135) | 587.5 小时、370,000 句、100 多位教师；真实在线英语教学中的教师语音 | 可作教育领域补充，软件技术场景匹配度较低 | 论文称开放，但当前具体许可证及有效下载入口未核实 |
| [SEAME](https://catalog.ldc.upenn.edu/LDC2015S04) | LDC 目录约 192 小时录音、156 人；新加坡/马来西亚自然对话与访谈 | 授权后可做不同口音、地域的外部验证 | LDC 许可；目录录音时长不可直接当作某个标准评测划分的时长 |
| [ASRU 2019 混说挑战](https://arxiv.org/abs/2007.05916) | 500 小时纯普通话训练 + 200 小时混说训练 + 40 小时混说开发数据 | 参考 MER 定义与经典方法 | 历史参赛数据，不代表当前可直接公开下载；本轮未核实获取授权 |

这些公共数据主要是自然交谈或教学。“有 technology 主题”不等于覆盖 PyTorch、LoRA、Kubernetes 等密集专业术语，也不等于代码、路径、版本号的真实听写场景。

## ASCEND：优先跑通基线

依据：[论文](https://arxiv.org/abs/2112.06223)、官方数据卡。

- 官方划分：train 9,869 条，validation 1,130 条，test 1,315 条；采样率 16 kHz，论文平均片段约 3.1 秒。
- 全集按语言统计：中文 6,139 条 / 5.32 小时，英文 2,850 条 / 2.42 小时，混说 3,325 条 / 2.88 小时，混说占 27.01%。这些是**全集**统计，不能把 test 的 1,315 条全部叫作混说测试。
- 提供 `language`、`original_speaker_id`、`session_id`、`topic`、`duration` 等字段，便于分层评测。
- 五类主题包含 technology；该主题句内混说占比 31.93%，但论文例子包括社交媒体和智能手机。需要抽样核查，不能假设它是软件工程术语集。
- 论文设计为说话人独立划分；实际导入仍应检查说话人与会话是否交叉。
- 可以分别报告 mixed 主结果，以及中文/英文样本的误改控制结果，避免总体均值掩盖混说表现。
- 会话字段不等于可直接还原完整对话。若使用历史上下文，需先核查时间信息、排序及片段缺失情况。

数据卡 `download_size` 约 1.22 GB；test 的逻辑数据字节数约 106 MB。这是元数据口径，不是实际网络下载量或本机下载验证。

## CS-Dialogue：更适合上下文，但先核清条款

依据：[论文](https://arxiv.org/abs/2502.18913)、官方数据卡。

- 200 位说话人来自中国大陆 30 个省级地区，英语较熟练；100 场双人对话对应 200 份分轨原始录音。104.02 小时不应误解为 100 场对话的墙钟时长。
- 官方划分：train 140 人 / 26,428 条 / 68.97 小时；dev 30 人 / 6,196 条 / 18.30 小时；test 30 人 / 6,293 条 / 16.74 小时。论文说明划分为说话人独立。
- 有完整对话和短句索引，适合构造“只使用当前句之前信息”的上下文实验；主题包括 technology、education、job 等，技术术语覆盖仍需抽样。
- 数据卡标注 **CC-BY-NC-SA-4.0**，并列出附加访问条款：仅学术/教育和非商用研究，明确禁止商业产品开发；禁止第三方再分发，衍生数据的组外分发也受限制。
- 本轮 API 返回 `gated=false`，但卡片同时存在申请字段及访问条款。不能据此断言“必须申请才能下载”，也不能认定“可无条件使用”。实际获取流程与本项目研究用途是否适用，需以维护方条件为准。
- 建议仅在确认适用授权后用于独立研究评测，不随 FlowType 产品打包；不使用镜像或派生数据绕过原集条件。

主实验应使用**历史 ASR 预测**作为上下文，保留真实错误传播；历史人工转写只能单列为 oracle 上界，不能混入可部署方案的主结果。

## 其他候选为什么暂不优先

### TALCS

论文描述真实一对一在线英语教学，但数据仅含教师语音，不能当作完整双人对话。训练/开发/测试分别为 350,000 / 5,000 / 15,000 句，555.9 / 8.0 / 23.6 小时；句长 0.3–30 秒。

内容偏语法、阅读、写作；标注英语大写，并清除部分符号，不适合直接评估代码、路径与符号保真。[论文所指官网](https://ai.100tal.com/dataset)本轮可访问，但所见页面未核到 TALCS 的有效下载入口或具体许可证。暂不作为首周实验的依赖。

### SEAME 与 ASRU 2019

SEAME 是经典中英混说资源，但口音地域与目标不同，且需要 LDC 授权。文献中不同规模常对应不同标注版本及切分；后续必须固定版本、转写阶段和 split，不能把目录的约 192 小时与某篇论文的标准评测数字混用。

ASRU 2019 的 500 小时是纯普通话训练数据，混说部分为 200 小时训练和 40 小时开发。可参考混合错误率定义，但不能把当年的参赛者可用数据写成当前无门槛公开集。

### CS-Dialogue-DPO 派生集

[数据卡](https://huggingface.co/datasets/ngqtrung/cs-dialogue-dpo)描述的 rejected 文本来自 Qwen3-32B 根据参考转写合成的翻译错误，并非实际 ASR 输出；卡片也记录 chosen 与 rejected 相同的样本。它可作为后续方法线索，不能替代真实 ASR 纠错评测，也不构成与 CS-Dialogue 独立的外部测试集。仍需遵守原集条款。

## 建议补采：真实技术口述专项集

以下是建议，尚未采集或确认具体规模：先做 **150–300 条、多说话人、多会话**的小型真实录音集。若最终只有用户本人录音，必须明确结论仅覆盖个人使用场景，不能声称跨说话人泛化。

覆盖内容建议：

- LLM / PyTorch：LoRA、QLoRA、attention、batch size、learning rate、模型名称与缩写。
- 工程技术：Kubernetes、Docker、API、函数名、路径、版本和数字。
- 易错控制：近音术语、罕见词、极短英文、否定词、数字；同时保留原本识别正确的样本。
- 上下文条件：相关领域文档、相关历史口述、无上下文、无关或冲突上下文。给无关上下文时也应允许系统保持原文。
- 区分逐字转写和产品格式化：口述“斜杠”“点”等如何映射为符号应另立规则，不能把格式化差异直接归为声学识别错误。

录音、人工参考转写和上下文来源应分别留存，征得参与者同意并去除私密内容。TTS 可以辅助调试与压力测试，最终效果须用真实录音验证。自采专项结果与公共混说结果分别报告。

## 评测协议建议

### 固定输入与对照条件

对同一音频固定一次原始 ASR 输出，再成对比较：原始 ASR、现有规则后处理、无上下文 LLM 纠错、词表纠错、词表与历史上下文纠错；补充无关上下文负例。每个条件保留相同样本集合，避免同时换 ASR 模型导致收益归因不清。

固定并记录 backend、模型版本、运行时、解码参数、提示词、词表版本和随机设置。关闭自动模型降级，或逐条记录实际模型并分别统计。超时、空输出与失败不得静默剔除，须报告失败率并预先约定计分方式。

### 指标

主指标建议 **MER（Mixed Error Rate）**：中文按字、英文按词构成混合 token 序列，计算 `(替换 + 删除 + 插入) / 参考 token 数`。全量指标使用总编辑数除以总参考 token 数，不直接平均各句错误率。

辅指标包括：中文 CER、英文 WER、术语召回与误替换、原本正确 token 被改错的比例、改善/恶化句数、处理延迟及失败率。中英文分项应固定跨语言替换与插入的归属规则；术语指标固定匹配边界、大小写及别名规则，不能用宽松模糊匹配掩盖错词。

在看测试结果前冻结标点、大小写、空格、缩写、连字符、数字与版本号的标准化及 tokenization 规则。主 MER 可使用约定的规范化文本；数字、代码与符号另报严格保真结果，保留原始转写供审计。术语误改分母需明确，避免只报告改对的例子。

对配对结果可按说话人/会话做 bootstrap 区间，避免把相邻短句当作完全独立样本；小样本区间较宽时应照实报告。

### 防止答案与上下文泄漏

- 使用官方 train/dev/test 划分；调参、提示词与阈值只看 train/dev。自采数据按说话人/会话留出，技术模板和近重复内容也应隔离。
- 词表来自事先独立的领域文档或训练划分，不能从当前测试参考转写反向抽专属热词；保存来源和生成时间。
- 历史上下文只含当前句之前的信息，不包含未来对话。人工历史转写单列 oracle 条件。
- 冻结方案后只做最终测试；如果看完 test 又改方案，明确该集已用于开发，另留新的测试集。

## 研究定位与下一步

[Aligning Speech to Languages to Enhance Code-switching Speech Recognition](https://arxiv.org/abs/2403.05887)已有语言线索与 LLM generative error correction 相关研究。因此“把 LLM 接在 ASR 后面”不能直接声称为原创算法。本项目应通过技术领域约束、负例下的保守修改和可复现实验说明具体贡献；是否有效仍待实验。

建议下一步先检查 ASCEND validation 的音频、标注和技术词分布，再明确专项集采集规范与纠错方法设计；无需先下载所有大数据集或训练模型。本轮没有为任何模型或方法生成性能结论。
