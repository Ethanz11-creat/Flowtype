# M4 failure and recovery inventory

Source baseline: `68c72d4` (HEAD observed 2026-11-02). Read-only source research; no builds, test execution, network, GUI, user configuration, credentials, local models, or audio were accessed. This document is the only authored artifact. Scope is the five pipeline stages, errors they receive, and recovery/readiness/M3 test contracts. The controller/UI is a separate audit; only the existing action enum and tests of its public recovery behavior were inspected here.

## Main finding

The pipeline has typed low-level failures but no `FailureKind` or `RecoveryAction` domain model. `ErrorRecoveryContext` is only `failedStage: String`, `error: Error`, `rawText: String?`, and `retryable: Bool` (`Sources/flowtype/Core/Pipeline/PipelineStage.swift:38`). The primary classification loss occurs at `ASRStage.swift:171`: terminal suspension after an unsuccessful provider chain uses a generic, retryable `ASRStageError.transcriptionFailed` except a first `RealtimeASRConfigurationError`. Even the preserved realtime configuration error is marked retryable. HTTP authentication/configuration/permanent rejection, unavailable engines, unsupported local model language, and transient timeouts therefore cannot reliably drive different recovery actions.

M4 should add typed classification and a deterministic recovery policy at the stage boundary while retaining M3's complete-payload, cancellation, literal-preservation, and no-repeat-delivery guarantees. It does not need a new provider retry loop, transport replacement, model lifecycle rewrite, or persistence of raw audio.

## Smallest coherent M4 classification

This is a proposed contract, not an assertion that these types exist.

1. Add a pure, typed `FailureKind` representation to the recovery domain and populate it where cause is still known. A minimal useful set is `cancelled`, `permissionDenied(permission)`, `engineUnavailable`, `authentication`, `configuration`, `transient`, `invalidAudio`, `recordingInterrupted`, `deliveryNotDispatched`, and `otherPermanent` (including invariant/permanent request rejection). Use small associated enums only when they change an action or safe message. The precise names are less important than preserving these separations. Optional polish rejection can remain a nonblocking completion notice; it does not require an extra suspend kind.
2. Keep `retryable` derived from a recovery policy instead of allowing contradictory independent inputs (`kind=configuration`, `retryable=true`). If migration requires retaining it, classifier output must be authoritative and cancellation/invalid-audio/delivery rules must override the legacy flag.
3. Map typed **error plus stage/payload availability plus delivery evidence** to permitted actions. Error alone cannot establish valid saved PCM, distinguish postprocessed/raw/final text, prove a delivery was not dispatched, or distinguish stopping from canceling recording.
4. Reuse the current action vocabulary where possible. `retry(stage: ASR)` means reprocess valid complete retained audio after a user click. It never means restart recording or reinsert text. If the product adds a `rerecord` action, it starts a new session/capture; it must not call retryFailedStage on malformed/interrupted PCM. Without that new command, a clear rerecord notice plus normal start control is sufficient.
5. Recovery candidates: microphone → settings/recheck/dismiss; auth/config → ASR settings/recheck/dismiss; unavailable engine → existing readiness policy actions; transient ASR + valid saved audio → retry ASR/dismiss; invalid PCM/interrupted capture → new capture/no same-payload retry; no text and invariant error → safe notice/dismiss; nondispatched delivery + complete final text → copy result/dismiss. Cancellation → no actions. A dispatched uncertain result → existing history recovery, no retry/reinsert action.
6. Preserve the captured route and complete saved audio during explicit transient retry, and renew the completion budget as today. Changing credentials/model/language after settings repair does **not** automatically refresh the immutable captured route (`ASRRouter.swift:5`). The smallest M4 can require starting a new recording after configuration repair/recheck; if “repair then retry same recording” is promised, it needs an explicitly designed new route snapshot and regression tests. Merely adding Settings + Retry buttons to the current snapshot repeats stale configuration.
7. Keep the existing one-pass fallback chain. Classify terminal failure before flattening at `ASRStage.swift:171`; separately handle empty candidate IDs. Classifying only `buildErrorActions` cannot recover discarded types. Document and test selection for mixed candidate failures: firstFailure currently wins, while an expired budget overrides displayed message. A later unavailable provider or timeout must not accidentally turn known bad credentials into an unchanged retry; conversely a successful fallback must remain successful. A compact collection of safe per-attempt kinds is preferable only if multiple repair actions are actually needed; no raw messages need be retained.
8. No new automatic provider retries. Known transient class means an explicit user retry is permitted, not that the stage should resend. Keep redirect refusal, fresh realtime handles, cancellation checks, and one-winner selection unchanged.

## Focused M4 regression requirements

Use existing fake providers, synthetic PCM, in-memory configuration, and fake delivery/transport seams. No live permissions/model/network/audio are needed to prove the policy.

1. **Typed classification matrix:** all `CloudASRError` cases; HTTP 400/401/403/404/413/429/5xx plus conservative unknown/redirect; realtime config cases; known typed cancellation variants; speech notAvailable; Whisper unsupportedLanguage/invalidSampleRate; arbitrary unknown Error. Assert kind, safe message, and allowed actions, not implementation-specific strings alone. Include hostile provider message/userInfo fixtures to prove no secrets/content get retained or shown.
2. **Real ASR stage preservation:** inject a provider throwing typed HTTP 401, configuration noModel/invalidURL, transient timeout/network, and unavailable engine. With nonempty valid samples/no preview and no successful fallback, assert resulting recovery kind/actions remain distinct. Provider-level tests alone miss today's flattening. Empty candidate IDs should produce explicit no-engine/settings behavior with zero provider calls.
3. **Mixed route failures and success:** cloud auth → local success remains successful with exact original audio; cloud auth → local unavailable/timeout has deterministic repair policy; local unavailable → transient cloud has deliberate policy; canceled first attempt starts no next provider. Assert no additional implicit provider calls and existing health accounting is not silently changed.
4. **Explicit transient retry integration:** keep M3 fresh-budget/fresh-handle/exact-PCM assertions; no provider request until explicit action; retry once uses complete saved payload, reruns preflight, preserves polish flag, stores one winner/history, no rerecord. Test stale retry callback after cancellation/new session cannot invoke provider.
5. **Invalid PCM versus rerecord:** keep NaN/infinite/out-of-range/tail invalid tests and zero route/provider/health/history/delivery. Invalid audio must have no saved-audio retry even if a legacy context claims retryable=true; if `rerecord` exists, assert new capture/new session rather than resending malformed payload. Silence/empty stay gentle notices and cannot promote preview.
6. **Permissions and recording:** normalize both PermissionError.microphoneDenied and AudioRecorderError.permissionDenied. Test pure mapping for engineStartFailed/formatCreationFailed → new capture/device repair. A real recording-stage regression requires a narrow recorder seam; do not hit real mic hardware. Do not accidentally call microphone repair for Apple speech permission or treat absent AX as fatal when clipboard is available.
7. **Permanent configuration repair and route identity:** settings/recheck must not implicitly send saved audio. If repair-then-retry same audio is supported, assert replacement route uses repaired snapshot while an old in-flight callback cannot alter it; otherwise assert old retry is cleared and next recording captures new route. Cover forced-policy no-engine/auto action reuse.
8. **Text availability/provenance:** postprocess invalid input nil; empty result actual original only; Injection recovery copies full final result, not raw ASR or partial typed prefix. Cancellation suppresses copy despite available text. Do not add a retry delivery action to nondispatched failures unless a separately designed explicit re-targeting operation owns a new attempt.
9. **Polish remains optional:** no-config/auth/timeout/incomplete stream/damaged literals all deliver full processed fallback once; no partial output or blocking ASR retry card. Keep backtick/URL/path/flag/version/numeric literal tests and destination-neutral notices.
10. **No resend after uncertainty:** reuse M3 delivery fixtures for error/cancel after actual first Unicode/newline/paste event. Neither classifier nor a stale retry action may type/paste/copy again. Before-event rejected paste/fallback retains original multi-format clipboard until explicit copy. Temporary write without event stays canceled, not uncertain. Once-only history/summary and newer-session ownership remain intact.

## Specific risks/limits for the implementation plan

- **Classification too late:** `ASRStage.swift:171` already discards cause. Changing UI action mapping alone cannot distinguish authentication/configuration/transient failures.
- **String classification:** current `ASRStageError.transcriptionFailed(message:)` and `LLMError.apiError(String)` permit arbitrary text. Do not parse localized “请重试” or substring “401” as M4 policy. Safe typed HTTP status exists for ASR and should be used directly.
- **Ambiguous transients:** invalidResponse, invalidEvent, unknown realtime taskFailed, arbitrary errors, and DNS failure are not definitive proof of a transient service issue. Explicit one-shot user retry may be allowed by policy, but no automatic resend and no invented authentication diagnosis.
- **Immutable route after settings:** `ASRRouter.swift:5` guarantees identity/credentials for a session; an explicit retry under today's mechanism reuses it. Repairing settings without starting/rebinding route cannot repair old credentials or model/language.
- **First versus terminal failure:** `ASRStage.swift:142` keeps firstFailure, `:172` conditionally changes timeout display. Choose a deterministic safe precedence before coding; don't unintentionally classify only the last failure or let budget expiry erase useful config repair.
- **Cancellation is stage dependent:** Recording task cancellation can mean stop; Injection cancellation after event means uncertain dispatch and history recovery. A blanket “every CancellationError means no stored outcome” rule would regress M3. Actions still remain suppressed for canceled sessions.
- **Delivery is not idempotent:** `InjectionStage.swift:157` completes uncertain after first event. A generic retryable error Boolean must never reset ownership/event latches or reinsert uncertain text.
- **Privacy regression through preserving Error:** cloud HTTP strips body and userInfo, while realtime taskFailed carries provider message. Preserve safe kind/status/code, not arbitrary raw error descriptions or full service payloads.
- **Device evidence gap:** `AudioRecorder.swift:299` swallows engine-start errors outside CoreAudio domain into an ended stream; conversion failures can look like empty capture. If M4 promises precise device diagnostics, one narrow propagation seam is needed. A taxonomy alone does not fix this, and broad recorder rewrite is unnecessary for initial failure classification.
- **Recovery actions already exist:** renaming/wrapping `SessionController.ErrorAction` should not duplicate commands or change working readiness/M3 labels. The missing domain is cause + safe permitted recovery, not another set of button strings.

## Suggested minimal delivery order

1. Introduce the pure failure classification/policy with safe typed evidence and action eligibility, keeping existing UI commands compatible.
2. Wire ASR terminal/no-candidate paths before cause is erased; normalize recording permission/device errors; keep optional polish and Injection outcomes as they are.
3. Add typed matrix plus real-stage and explicit-retry integration tests; keep M3 safety tests as regression gates. Only add recorder propagation or repair-then-same-audio route rebinding if those behaviors are explicitly in the M4 product scope.

This research did not execute validation; all test conclusions above describe assertions present at baseline, not a fresh passing run.
