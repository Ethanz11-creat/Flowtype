# 上下文 ASR 纠错：探索性配对实验

日期：2026-11-11。承接[原始识别基线](../2026-11-11-asr-baselines/README.md)。这是文本后置纠错实验，不是声学模型训练或 ASR 解码期热词注入。

## 问题与假设

已提供含干扰项的正确候选词表时，LLM 后置纠错能否降低英语长尾词错误，并控制普通词误改？比较同一批冻结识别输出：原始 ASR、普通 LLM 纠错、带候选词表的保守 LLM 纠错。

主观察指标是官方 B-WER；同时报告 WER、U-WER，以及原本正确的句子被改错的数量。即使 B-WER 改善，也不能忽略 U-WER 退化和交互延迟。

## 数据与输入隔离

- 固定此前 LibriSpeech test-clean 自定义 200 条 pilot，40 位说话人各 5 条；不按错误筛选样本。全部样本参加所有条件。
- 原始 ASR 为 Qwen3-ASR-1.7B MLX 4bit，使用当前产品解码参数；原始预测 SHA-256 固定为 `04c1d1c8855f9705a9013bfaa28d5872aa410e111abd204224967301cc003bb9`。
- 普通组只发送原始识别文本。词表组额外发送官方 TSV 第四列的完整候选词表，包括干扰词。官方“100 词表”不是每句恰好 100 个词，不截断、不筛选、不排序重组。
- 推理输入不含参考转写、第三列实际目标稀有词、逐句错误标签、说话人或音频。参考只用于准备完整词表及推理结束后的评分。
- 这组官方词表构造保证含目标词，是理想先验；实验不检验真实上下文检索召回率，也不直接证明中英技术口述的产品收益。

## 固定条件

- 使用当前已配置的硅基流动 `deepseek-ai/DeepSeek-V3`；temperature=0、max_tokens=512、非流式；同一服务、模型与基础提示词。
- 词表条件仅增加候选词字段及如何保守使用含干扰候选词的提示。因提示长度不同，不能将差异完全归因于某个内部推理机制。
- 基础提示要求最小、确信的识别纠错，保留措辞、否定、数字、重复和语言；不改写、补全或摘要。不加入根据 pilot 错误案例提炼的特定词规则。
- 首先用前两条进行 4 次接入检查，确认接口与返回格式正常；未据此调提示词。随后重新运行完整 200 条。接入请求与完整实验分开留存。
- 在第一条请求前写入机器协议，冻结完整提示、参数、脚本/输入/来源哈希与开始时间；请求按每句普通组、词表组交错提交，4 路并发。
- 不自动换厂商、模型或重试。超时、HTTP 错误、空响应、截断、错误结构均保留原 ASR 文本，显式记为 fallback；所有 fallback 参与有效管线计分，并独立报告数量。不得按成功请求筛样本。
- 仅提交公开语料的识别文本及候选词；不提交用户录音、历史记录或应用上下文。密钥仅内存读取，不写入归档或进程参数。

## 评分

- 使用与原始基线相同的固定官方评分脚本和假设文本规范化。官方 B/U 按第三列参考稀有词划分，插删代价 3、替换代价 4 决定对齐路径。
- API 失败时有效输出为原始文本；评分适配文件统一记为有效管线输出，不能将适配文件的 `failure_count=0` 解释为没有 API 失败。API 失败以 `completions.jsonl` 和对照汇总的 `fallback_count` 为准。
- 另以单位代价词编辑距离诊断每句 improved / harmed / same_error_count，以及原本零错误的句子被改错的数量；它和官方加权对齐下的 B/U 聚合指标分开。
- 全部 400 个 `(id, condition)` 必须唯一且齐全，否则不出完整评分。baseline、候选来源和推理输入哈希必须匹配；fallback 必须逐字保留原始文本。
- 记录服务报告的模型名、token 用量、中位与 p95 请求耗时。耗时含网络、排队与服务推理，不是模型纯推理或客户端端到端延迟。

## 结论边界

原始输出和部分标注已经查看，当前为探索性 pilot，不是独立盲测。temperature=0 也不保证第三方服务可逐字重现；请求模型别名可能随服务端更新。仅凭 200 条英语有声书不能声称统计显著、中文混说泛化、软件术语准确率或产品发布质量。

后续正式验证需要冻结方法后使用未见留出样本，并补充混说误改控制及真实技术词/真实外部上下文。若根据本次案例改提示词，应另建版本，不覆盖本次结果。
