# M2 模型修复与降级设计

日期：2026-11-01。基线：flowtype-local / b9930bd；承接稳定性设计 §4.3.3 / M2。
状态：供 Owner 审阅的具体设计；产品代码尚未改动。

## 目标与已确认的选择

把现有 Qwen 模型下载从不透明的重复失败变为可诊断、可恢复的操作。
完整本地模型优先离线加载；下载失败能看到真实模型、源、状态和恢复动作。
Owner 已明确选择：自动推荐 1.7B 失败后再试一次 0.6B，成功显示降级；
手动选定 1.7B 不自动覆盖。普通重试仍遵守用户当前选择与下载源。

保留本机已可用 1.7B、模型目录、应用 URL 缓存、API Key、ASR 路由策略。
只在既有 flowtype-local 工作树开发；不 push、不 merge、不改历史。
不新增云端 ASR/LLM 服务商，不做 M3 自动交付、M4 全局失败分类或 M5 CI。
新增网络请求仅为所选公开模型的元数据；不包含音频、上下文或用户凭据。

## 方案选择

1. **推荐：现有流程增量加固。** 独立、可注入的元数据预检和错误分类；
   QwenModelState 统一协调自动加载、重试、手动下载/取消和恢复；继续使用
   speech-swift 下载/加载。保留 ModelDownloader 的 UI 兼容入口，转为委托。
2. 修改/维护 Hugging Face 依赖分支，改变重定向和缓存实现：长期可能有益，
   但扩大依赖维护范围且无法使不可达的官方源变得可达。
3. 自建权重下载器或调用 curl：需要 manifest、断点/完整性/进度/取消等新协议，
   这轮不做。不得把 M0 的手工下载脚本悄悄变成产品运行时依赖。

选择方案1。预检用于快速、准确地解释失败；它不能保证整个下载成功，
也不能修复镜像按客户端返回错误重定向的外部服务行为。

## 元数据预检

- 使用 URLSession / CFNetwork，10 秒请求超时；ephemeral、urlCache=nil、
  reloadIgnoringLocalCacheData；不删除或改写应用现有 URL 缓存。
- 对选中端点的 `<repo>/resolve/main/config.json` 做 HEAD，Accept-Encoding=identity。
  不 GET 权重、不上传内容。跟随同源相对重定向并保留 HEAD，最多5跳；
  不自动跨源跟随绝对重定向，不在日志或 UI 输出 Location 的 query/userinfo。
- 采用与当前 Hub 元数据消费兼容的判定：HTTP 200，或带完整元数据的
  302 文件下载重定向；要求非空 repo commit、非空 etag、正数 size、有效位置。
  308/其他拒绝跳转及缺少任一元数据都立即 metadataInvalid，不盲重试。
  无效 URL、非 HTTP 响应、超时、离线、4xx/5xx 分别产生明确诊断。
- 摘要保存所选端点、repo、最终响应位置的安全摘要、HTTP状态与失败类别；
  不保存 auth、响应正文、signed URL query。允许 UI 显示宿主和安全路径。
- custom 下载源继续兼容；URL 不含 userinfo/query/fragment，公网 HTTPS，
  明确 loopback 可 HTTP；不把已保存 custom 显示成“官方”。

HEAD 成功只让现有下载继续。底层仍可能受缓存/后续文件/网络影响而失败；
该失败继续分类并给出切源、离线目录与真实命令，不声称已根治服务端问题。

## 错误与重试阶梯

模型专属 `ModelProvisionError`：metadataInvalid、network、stalled、
incompleteLocal、loadFailed，另保留取消与磁盘空间不足的独立结果。
错误按阶段和已知错误/HTTP信息分类；取消不归入失败、不触发降级。

每次操作快照配置和目标：

1. 按配置查找本地完整副本并离线加载，成功不发预检/下载请求。
2. 无可用副本则预检目标端点；失败及时给出诊断，禁止进入昂贵下载重试。
3. 预检通过后当前推荐 preset 最多3次下载/加载；仅瞬时网络错误继续退避
   （10秒、20秒）；元数据、目录、加载/磁盘等确定性失败不机械重复。
4. 自动模式的推荐1.7B用尽可用尝试后，0.6B额外一次（包含自己的预检）；
   显式1.7B不切换。无递归降级、无取消后降级、无失败后自动重新开启整轮。
5. 0.6B成功时 selectedLocalModelID 保持 nil，active model 真实标为0.6B，
   显示“已退回 0.6B”；下次启动优先按既有本地搜索选择可用模型。
6. 手动“改用0.6B”明确写入选择并立即启动该模型恢复；清除冲突的自定义
   目录选择必须属于该显式动作，不能在自动降级时暗改用户路径。

停滞 watchdog 沿用30秒无进度判定；状态必须对应真实重试或终止，
不允许常驻“正在自动重试”却没有任务。取消、重试、重复点击和晚到回调
由操作ID隔离；一个旧任务不得覆盖新状态或卸载新模型。

## 生命周期与模型身份

现有两个入口会同时操作共享 Qwen provider，手动下载甚至会卸载现用模型。
本轮用 QwenModelState 单一协调入口，串行化模型操作与 HF_ENDPOINT 使用；
ModelDownloader 保留展示接口但委托同一流程，不再先加载→卸载→再次加载。
不在取消尚未结束的底层工作后并发开启另一轮；旧回调检查 operation ID。

QwenASRProvider 在新模型加载成功并通过取消/所有权检查前保留旧模型引用，
不预先 unload。失败/取消不能使原来 ready 的模型变为不可用。
状态分别记录“可用模型身份”和“当前恢复操作/失败摘要”；可用旧模型仍使
readiness保持可用，同时卡片解释目标模型操作失败，避免显示新模型已就绪。
保留当前推理队列隔离；不把 MLX 模型跨线程当作 Sendable。

ModelLocator 的显式预设选择必须在 legacy 缓存搜索时也保持身份匹配，
不能把0.6B缓存以1.7B名义返回。自定义目录优先按配置/可识别信息确定身份，
不能仅凭体积猜成另一型号；不扩展任意第三方模型 family 支持。

## UI 与引擎状态

- QwenModelStatusCard / ASRModelStatusCard / LocalModelPicker 使用同一实际目标
  和可用模型身份；repo、下载命令和目录跟随当前预设，不再硬编码0.6B。
- 错误展示可理解的分类、源、最近HTTP状态和简短说明；提供重试、切源、
  指定文件夹、复制命令，以及显式1.7B失败时的“改用0.6B”。
- 指定目录经过现有完整性校验后立即离线加载；统一使用当前自定义目录字段，
  保留旧 localModelPath 读取兼容，避免两个 picker 写入不同字段却互相覆盖。
- 源切换改变后续重试的快照，不中途重定向现有任务；文案明确“重试时使用”。
- 已有 Readiness 的 Apple-only degraded/basic 分支保留，补核其展示；
  不在 localOnly/cloudOnly 下偷偷采用 Apple，也不新发 Speech 授权请求。
- Onboarding 完成前显示当前引擎是否可用；无引擎时“稍后配置”仍可完成，
  同步刷新 readiness 并提供修复入口，不误称已就绪。

## 测试与验收

平台保持 macOS15+/Swift6.2/SPM。依次 swift build，再 swift run FlowType --self-test；
CLT机器不跑swift test。测试使用URLProtocol/注入时钟和loader、临时目录，
不访问真实配置/模型/Key、不触发系统权限或下载GB权重。

覆盖：200完整元数据、已观测308无头、302完整头、缺字段、相对跳转、
10秒超时/HTTP错误/脱敏、预检失败零loader调用、3+1与显式不降级、
取消/停滞/晚回调/重复点击、旧模型保留、真实身份和legacy缓存不串型号、
目录导入后加载、readiness与onboarding稍后配置、错误后可再次重试。

控制器可用真实CFNetwork仅获取两个公开preset的config元数据，记录状态与
源，不把结果当作大文件下载成功。实际下载/切源/指定目录/降级卡片分别留
真机结果；未执行变体明确Pending。禁止删除当前模型以制造失败。
