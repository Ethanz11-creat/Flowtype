# 胶囊状态与 Typeless 对照审查

日期：2026-11-03。范围：现有 Swift 源码、浏览器原型以及 Typeless 2.8.1 逆向证据的静态审查。未修改产品代码，未执行真机测试。本文件为发现和建议，不代表状态改版已经获批或实现。

## 结论

现有会话生命周期和 M4 恢复策略基本合理，应保留。主要不足集中在展示层：后台识别/整理的表达、交付方式的诚实提示、长 notice 的布局和寿命、以及慢处理反馈。此前浏览器原型只覆盖部分状态，不能作为前后端全部对齐的证明。

已确认的普通胶囊基准为 **216 × 54，原版蓝紫与雾面，13 / 11 字号**。原生源码目前仍为 240 × 70；本次审查同时考虑后续尺寸落地。需要操作的异常使用展开恢复卡，不受普通胶囊尺寸约束；具体异常外形仍未定。

## 优先处理的展示问题

### 1. 紧凑尺寸不适合任意长消息作为标题

`SessionState.statusTitle` 把整个 `.notice(String)` 原样作为标题；`CapsuleView` 标题没有明确行数合同，副标题为空。现有 HStack 的水平 padding 共 40，音柱占 40，主间距至少 14；216 宽下留给文字约 122，长句可能多行、截断或被外形裁掉，不能直接把新尺寸套到旧文案。

例子包括“焦点已变化 · 已复制，按 ⌘V 粘贴”“技术内容已保留 · 已使用识别结果”和资源收尾提示。此前浏览器的 notice 演示只有一种简短无语音场景，尚未覆盖这些真实文案。

建议展示层采用明确的短标题 + 副标题 + 图标 + 停留策略。普通消息用两行表达；长失败说明进入恢复卡。不得通过缩字号或从头截断掩盖原因。

### 2. “完成后自动输入”承诺过早

`CapsuleView.statusSubtitle` 对 processing/polishing 使用同一句话，但 InjectionStage 可能因为辅助功能、焦点变化或目标不可写转为仅复制。建议换成当前阶段的中性描述，交付方式确定后再明确提示“正在输入”或“结果已复制”。

### 3. 停留时长应按信息目的区分

现有所有 notice 统一 2.2 秒，包括无声、降级与需要用户手动粘贴的信息。建议短无声/降级约 2–3 秒，复制交付约 5 秒，真正需要设置/重试/复制恢复操作的卡片常驻。慢处理提示属于活动会话，不应经 terminal notice 路径结束或释放会话。

这些时间是待验证提案，不是 Typeless 常数的照搬。新会话必须立刻抢占旧提示，旧计时器不得关闭新会话。

### 4. 左侧图形没有完整的状态语义

原生 CapsuleView 只有“spinner / AudioVisualizer”两种分支，输入中、notice 和 error 目前都复用低矮静态音柱。建议录音专用波形，准备/识别/整理用进度符号，复制/警告/权限/不确定使用对应静态符号；底色与蓝紫身份延续已确认视觉。

AudioVisualizer 即便录音电平为零也有基底高度，且整块呼吸独立于声音。它不是已检测到人声的证据。若后续调整，静音回落为安静基线，不能显示“检测到语音”的假信号；保持用户选定的材质和颜色。

### 5. 失败标题与资源要对齐

RecoveryPolicy 已按类别区分动作，CapsuleView 却统一使用“出错了”作标题，把原因压进较小副文字。建议沿用原策略，让权限、识别未完成、录音中断、检查输入结果等成为标题。

另一个静态不一致是 `RecoveryPolicy.transientASR` 的 message 无条件写“可重试原录音”，按钮却仅在 `stage == ASR && hasAudio && !deliveryEventStarted` 时出现。该句不能成为通用 UI 模板；无原音频时只应提示重新录音。此审查未构造运行时反例，属于展示合同风险。

## 应保留的现有行为

- 不显示实时转写，不增量落字，首个有效音频缓冲才进入录音。
- 一次交付、取消隔离与旧恢复卡身份校验。
- 静音不等于权限拒绝；不确定识别条件不轻易丢弃录音。
- ASR 重试只重处理确有的原音频；重新录音是另一动作。
- 不确定交付无自动重发，不凭 500 ms 等延时承诺成功。
- 需要操作的恢复常驻；不能因为“错误较轻”而让唯一入口几秒消失。

## 后续落地边界与验证

建议增量整理展示模型，由真实 SessionState、RecoveryCard、交付结果和当前会话经过时间派生，不为每个副标题新建一套业务状态机。展示内容不解析 provider 原始错误字符串，不暴露识别文本或内部术语，也不据离线/弱网猜测服务原因。

需要分别验证普通 216 × 54 的真实文案、倒计时和翻译后的长度；错误卡长说明与最多四动作；所有 notice 的关闭/重入；慢处理计时与 20 秒预算；取消后无晚到提示；复制提示不被降级文案覆盖；无辅助功能时的菜单操作路径。

Typeless 有条件显示的完成/取消按钮。FlowType 普通胶囊目前没有这两个入口，主要依赖快捷键、Escape 与菜单。Escape 的全局处理依赖 event tap，不能在未授权辅助功能的情况下承诺可用。若要加入鼠标完成/取消，需要单独验证 216 宽内的布局、拖动冲突和非激活焦点行为，本次不顺带加入。

本轮仅静态审查和文档记录，没有运行构建或测试，也没有把已完成的 M1–M5 后端工作标记为未实现。
